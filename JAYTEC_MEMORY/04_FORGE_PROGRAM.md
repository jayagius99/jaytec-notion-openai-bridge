# JAYTEC Durable Memory — Forge Program

## Program structure

Forge should be treated as a general cognitive-system architecture, not merely a
collection of agents.

The reconciled executable Forge master program is G00-G37. Earlier planning had
two sets of 12 requirements/domains. Preserve their intent conceptually, but do
not create competing executable checklists.

## Cognitive direction

Core loop:
observe -> understand -> hypothesize -> plan -> act -> inspect -> critique ->
revise -> learn -> continue until convergence.

Distinct memory types should include:
- working;
- episodic;
- semantic;
- procedural;
- causal;
- failure memory.

Memory should change future behavior. Convert experience into tested procedures,
causal lessons, failure guards and improved planning.

## Owner and Human Specialist interfaces

Keep two distinct interfaces:
- Owner/Jay interface for ultimate authority, approvals and overrides.
- Human Specialist interface for ordinary operational interaction.

Human Specialist input is specialist input, not owner authority unless it enters
through the Owner interface.

## Anchor / Mobile Specialist

A dedicated mobile node is an external protected specialist/resource adjacent to
the cognitive core. It is not source of truth or owner authority. Use
capability-scoped APIs, trust states, revocation and recovery. Compromise of the
node must not compromise Forge or ROOT_OWNER.

## Upgrade direction

V2: reliable Admin/Command Hub and execution fabric.
V3: stronger self-upgrade/test environment, technical sovereignty and Full
Control Lab/Proving Grounds.
Later versions: lawful autonomy, resilience, internal capability and reduced
provider dependence while retaining owner control and auditability.
