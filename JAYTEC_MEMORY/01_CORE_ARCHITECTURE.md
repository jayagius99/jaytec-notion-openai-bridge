No subordinate component inherits owner authority merely because it has tool or
connector access.

## JAYTEC Project and JAYTEC System

The JAYTEC Project is the owner-controlled durable workspace/computer used to
build, operate and evolve JAYTEC. The JAYTEC System is the live orchestration
fabric running inside that workspace.

JAYTEC V2 direction is an Admin/Command Hub: issue high-level commands, inspect
state, manage specialists/workflows, review evidence, approve/block actions,
track upgrade readiness and initiate major projects.

## Infrastructure

- GitHub: code, branches, pull requests, CI, durable evidence and control notes.
- Render: runtime services, bridge and recovery endpoints.
- Neon/Postgres: durable task/runtime state where configured.
- OpenAI: SOL provider route when explicitly active.
- OpenRouter: selected bounded external specialist routes when explicitly active.
- Notion: optional structured gateway/state bus when explicitly used.
- Notion Agent: never an autonomous JAYTEC executor/planner/recovery path.

## Long-term technical direction

Move toward owner-controlled, vendor-independent infrastructure while keeping
external AI providers replaceable specialists rather than authority. Prefer
private networking, capability-scoped APIs, resilient workers, owner-controlled
secrets and databases, local/open-weight models where useful, and graceful
provider replacement.

Technical sovereignty must not remove owner override, auditability, revocation,
legal compliance, cost controls or isolation between critical components.
